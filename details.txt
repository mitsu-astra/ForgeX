1. EXECUTIVE SUMMARY & PROBLEM STATEMENT REALITY CHECK
====================================================================================================

1.1 THE CORE PROBLEM
In modern high-throughput discrete and batch manufacturing lines, three critical dimensions constantly interact:
1. Product Quality (surface defects, micro-fractures, tolerances)
2. Process Capacity & Flow (cycle-time imbalances, work-in-process [WIP], machine utilization, downtime)
3. Manufacturing Economics (scrap costs, rework labor, throughput penalties, lost contribution margin)

Typically, factory systems analyze these dimensions in silos:
- Quality teams inspect images with isolated vision systems.
- Production teams monitor machine telemetry and OEE dashboards.
- Finance teams review scrap costs and financial reports weeks later.

1.2 WHAT JUDGES ARE STRICTLY NOT LOOKING FOR:
- ❌ A generic standalone image classifier (e.g., standard ResNet script outputting class probabilities).
- ❌ An isolated KPI dashboard showing generic line charts without causal links.
- ❌ A basic annotation or labeling tool.
- ❌ A hallucinating LLM that invents numerical root causes or process metrics.

1.3 WHAT JUDGES ARE STRICTLY EVALUATING (THE REQUIRED SYSTEM):
- A unified industrial decision-support system that establishes an unbroken chain of evidence:
  1. Detects and classifies defects into acceptable vs. defective categories.
  2. Localizes defect regions spatially with explainable activation maps and bounding boxes.
  3. Quantifies epistemic uncertainty and detects out-of-distribution / novel defect types.
  4. Identifies manufacturing bottlenecks using operations research and Little's Law.
  5. Cross-correlates defect patterns with upstream process conditions using statistical correlation, CUSUM drift detection, and SHAP feature attribution.
  6. Quantifies the economic loss (scrap, rework, and lost throughput margin).
  7. Simulates what-if scenarios (e.g., reducing hydraulic pressure or adjusting conveyor speed) grounded in physical metallurgical principles.
  8. Delivers evidence-backed, confidence-weighted operational recommendations through an intuitive Next.js dashboard and an AI Factory Copilot.

1.4 SYSTEM CONSTRAINTS
- Software-Only & Advisory: No live camera feed, physical PLC wiring, robotic arm integration, or machine hardware control is required or allowed. All recommendations and interventions remain simulated or advisory.

3. THE WINNING END-TO-END SYSTEM APPROACH (THE 8-STAGE INTELLIGENCE CHAIN)
====================================================================================================

To satisfy all evaluation checkpoints and maximize scoring across the 100-mark rubric, the system must execute the 8-Stage Intelligence Chain:

    [SEE] -> [DETECT] -> [LOCALIZE] -> [CONNECT] -> [EXPLAIN] -> [PREDICT] -> [SIMULATE] -> [RECOMMEND]

Stage 1: [SEE & INGEST]
- Ingest visual inspection images (single upload, batch multi-file, or ZIP bundle).
- Standardize image geometry (224x224 RGB) and apply ImageNet normalization.
- Ingest manufacturing telemetry (CSVs from Model 1/2/3 or live batch parameter payloads).

Stage 2: [DETECT & CLASSIFY]
- EfficientNet-B4 deep neural network classifies the image into one of the 5 categories (`crack`, `hole`, `normal`, `rust`, `scratch`).
- Computes calibrated softmax class probabilities.
- Runs Monte Carlo Dropout (20 stochastic passes) to quantify epistemic uncertainty ($\sigma_{\text{MC}}$).
- Flags Out-of-Distribution (OOD) / novel defect types when maximum probability $< 0.75$ or uncertainty $> 0.15$.

Stage 3: [LOCALIZE DEFECTS]
- Extracts spatial gradient activations from the final convolutional block (`features[-1]`) using Grad-CAM.
- Computes class-discriminative saliency heatmaps normalized to $[0, 1]$.
- Applies adaptive Otsu binarization and morphological opening/closing to filter noise.
- Extracts tight defect bounding boxes ($x_{\min}, y_{\min}, w, h$), contours, and defect area percentage.
- (Optional enhancement): Feeds bounding box coordinates as prompt boxes to the Segment Anything Model (SAM) for pixel-precise segmentation masks.

Stage 4: [CONNECT & INTEGRATE]
- Maps the inspection result to the corresponding production batch ID, machine station ID, and timestamp.
- Retrieves upstream telemetry: station utilizations, queue times, cycle-time variance, and operating conditions (pressure, feed rate, pH, conveyor speed).

Stage 5: [EXPLAIN ROOT CAUSE]
- Executes three complementary explanatory engines:
  a. Statistical Correlation: Spearman rank correlation matrix identifying which continuous process variables co-vary with specific defect frequencies.
  b. Process Drift Detection: CUSUM (Cumulative Sum) quality control chart to detect subtle sequential drift before catastrophic batch failure occurs.
  c. SHAP Attribution: TreeSHAP on the Root-Cause Classifier generates local waterfall plots displaying the exact positive/negative contributions of each physical parameter.

Stage 6: [PREDICT BOTTLENECKS & IMPACT]
- Multi-output XGBoost Process Surrogate models predict station utilizations, queue growth, and throughput capacity.
- Applies Little's Law ($L = \lambda W$) and capacity constraint rules (utilization $\ge 85\%$ + queue buildup) to pinpoint the active bottleneck station.
- Deterministic Economic Engine calculates hourly, daily, and monthly financial losses:
  $\text{Total Loss} = (N_{\text{scrap}} \times C_{\text{scrap}}) + (N_{\text{rework}} \times C_{\text{rework}}) + (\Delta \text{Throughput} \times \text{Margin})$.

Stage 7: [SIMULATE WHAT-IF SCENARIOS]
- Interactive simulator allows engineers to adjust operating parameters (e.g., lower hydraulic pressure from 188 bar to 172 bar, buffer coolant pH to 7.7, throttle conveyor speed to 0.95 m/s, or increase station capacity).
- Grounded in physical metallurgy equations (Griffith fracture threshold, Pourbaix kinetics, Archard wear) to simulate realistic defect reduction percentages, throughput gains, and net monthly cost savings.

Stage 8: [RECOMMEND & INTERACT]
- Generates ranked, evidence-based corrective action items scored by Impact, Feasibility, and Statistical Confidence.
- AI Factory Copilot provides natural language explanations and interactive Q&A over the pre-calculated evidence chain, ensuring 100% factual fidelity without numerical hallucinations.

4. RECOMMENDED MODELS & ARCHITECTURAL COMPARISONS (WHY CERTAIN MODELS WIN)
====================================================================================================

4.1 VISION MODEL: DEFECT CLASSIFICATION, LOCALIZATION & UNCERTAINTY

RECOMMENDED PRIMARY MODEL: **EfficientNet-B4** (Pre-trained on ImageNet)
- Architecture Specs:
  * Backbone: EfficientNet-B4 compound scaled feature extractor (1,792 output channels).
  * Custom Classification Head: AdaptiveAvgPool2d(1) -> Dropout(0.3) -> Linear(1792, 512) -> ReLU -> Dropout(0.2) -> Linear(512, 5).
  * Target Layer for Grad-CAM: `features[-1]` (last Conv2dNormActivation block).
- Performance Achieved:
  * Test Accuracy: **99.94%** (1,799 / 1,800 test images correct).
  * Macro F1-Score: **0.9994** across all 5 classes.
  * Inference Latency: **11.33 ms / frame** on RTX 4050 GPU (363 FPS); ~32 ms on CPU.
  * Model Weight File Size: ~74.6 MB (compact and production deployable).

WHY EFFICIENTNET-B4 BEATS ALTERNATIVES:
1. vs. ResNet-50 / ResNet-18:
   - ResNet-50 is a traditional heuristic architecture with ~25M parameters. EfficientNet-B4 uses compound scaling (balancing depth, width, and resolution simultaneously) with mobile inverted bottleneck convolutions (MBConv) and Squeeze-and-Excitation (SE) attention blocks. This allows EfficientNet-B4 to capture fine-grained surface scratches and micro-cracks with significantly higher representation density and fewer FLOPs.
2. vs. Vision Transformers (ViT-B/16):
   - ViTs lack inductive bias for translation equivariance, requiring enormous pre-training regimes, and suffer from high quadratic latency on small image tiles. In high-throughput industrial inspection (where inference latency must be $< 20$ ms), ViT is excessively heavy without providing higher accuracy than EfficientNet-B4's 99.94%.
3. vs. YOLOv8 / YOLOv9 (Object Detection):
   - Crucial Hackathon Distinction: The dataset provided by organizers consists of image-level classification folders (`train/crack/`, `train/hole/`, etc.), NOT bounding-box annotated XML/YOLO text files.
   - Forcing a YOLO model requires manually pseudo-labeling 12,000 images, which introduces label noise and synthetic bounding box bias.
   - Using EfficientNet-B4 with **Grad-CAM + Otsu Bounding Box Extraction** represents the true state-of-the-art in Weakly Supervised Object Localization (WSOL). It directly produces class-discriminative activation heatmaps and extracts bounding boxes around the activation contours without needing manual box annotations.

UNCERTAINTY & OUT-OF-DISTRIBUTION (OOD) QUANTIFICATION:
- Monte Carlo Dropout:
  * Standard neural networks are overconfident even on out-of-distribution inputs.
  * By retaining dropout layers (`p=0.3` and `p=0.2`) active during evaluation and executing $N=20$ stochastic forward passes, the model estimates predictive epistemic uncertainty:
    $$\mu_c = \frac{1}{N}\sum_{i=1}^N P(y=c|x, W_i), \quad \sigma_c = \sqrt{\frac{1}{N}\sum_{i=1}^N (P_i - \mu_c)^2}$$
  * Epistemic uncertainty is quantified as the mean standard deviation across classes.
- Decision Thresholding (False-Reject vs. False-Accept Control):
  * Industrial rule: A False Accept (shipping a defective unit to a customer) is 10x more costly than a False Reject (re-inspecting a normal unit).
  * If $\max(\mu_c) < 0.75$ or $\text{Uncertainty} > 0.15$, the system flags:
    `Status: UNCERTAIN_NOVEL_DEFECT`, triggering human-in-the-loop review rather than guessing.

4.2 PROCESS MODEL: MANUFACTURING FLOW, BOTTLENECK & THROUGHPUT SURROGATE

RECOMMENDED MODEL: **Multi-Output XGBoost Regressors + Operations Research (Little's Law)**

WHY XGBOOST OVER DEEP NEURAL NETWORKS (MLPs):
1. Small Tabular Sample Size: The simulation dataset consists of 3,000 experiment samples. Deep neural networks on small tabular data are notoriously prone to overfitting, require heavy regularization, and lack direct feature transparency.
2. Training Speed & Robustness: XGBoost trains in less than 2 seconds, handles non-linear interactions across utilization and queue metrics without feature scaling, and achieves consistent $R^2$ scores across throughput and station utilization targets.
3. Native TreeSHAP Integration: XGBoost models can be evaluated using exact polynomial-time TreeSHAP algorithms (`shap.TreeExplainer`), providing mathematically guaranteed feature attributions.

PROCESS SURROGATE TARGETS:
- Model 1 (10 features): Predicts `Parts per hour` (Throughput), `Drilling Util`, `Milling Util`, `Assembly Util`, and `Assembly Waiting Time` given input `Demand`.
- Model 2 (16 features): Predicts `Entities Out`, `Drilling Utilization`, `Milling Utilization`, and `Assembly Utilization` given `Demand`, `Part 1 VA Time`, and `Part 2 VA Time`.
- Model 3 (77 features): Predicts station-level loads across Blanking, Press Cells 1-4, Assembly Cells 1-4, and Paint lines.

BOTTLENECK IDENTIFICATION ALGORITHM (OPERATIONS RESEARCH):
Rather than treating bottleneck detection as a pure black-box classifier, the system applies operations research principles:
- Rule 1 (Critical Utilization Threshold): Any station operating at sustained utilization $U \ge 85\%$ ($0.85$) is flagged as a high-severity capacity constraint.
- Rule 2 (Queue Divergence): If queue waiting time $W_q$ is monotonically increasing while downstream stations have idle capacity ($U_{\text{down}} < 0.60$), an operational bottleneck is confirmed.
- Rule 3 (Little's Law Alignment):
  $$L = \lambda W \quad \implies \quad \text{WIP} = \text{Throughput} \times \text{Lead Time}$$
  Computes WIP accumulation and lead time expansion caused by the bottleneck station.
- Line Balance Efficiency Metric:
  $$\text{Line Efficiency} = \left(\frac{\text{Mean Utilization}}{\max(\text{Station Utilization})}\right) \times 100\%$$

4.3 ROOT-CAUSE CORRELATION & STATISTICAL DRIFT ENGINE

RECOMMENDED ARCHITECTURE: **Multi-Class XGBoost Root-Cause Classifier + SHAP TreeExplainer + CUSUM Drift Monitor**

FAILURE MODE TAXONOMY (THE 5 ROOT-CAUSE CATEGORIES):
1. `storage_queue_corrosion` (Correlates with `rust`):
   - Mechanism: Parts lingering in intermediate buffers or warehouse queues experience atmospheric moisture exposure and coolant degradation.
   - Primary Drivers: Buffer Queue Time $> 2.5$ hours, Coolant $\text{pH} < 7.3$, High Ambient Humidity $> 65\%$.
2. `hydraulic_overload_stress` (Correlates with `crack`):
   - Mechanism: Press forming pressure or clamping force exceeds the material's elastic yield limit, initiating micro-fractures along grain boundaries.
   - Primary Drivers: Forming Pressure $> 180$ bar, Station Utilization $> 90\%$.
3. `conveyor_speed_friction` (Correlates with `scratch`):
   - Mechanism: Conveyor line velocity exceeds guide rail tolerance, causing vibration, part bumping, and abrasive sliding contact.
   - Primary Drivers: Conveyor Speed $> 1.10$ m/s, Transfer Time $> 45$ s.
4. `tool_wear_drill_misalignment` (Correlates with `hole`):
   - Mechanism: Accumulated spindle cutting cycles dull drill bit cutting edges, causing bit wandering, irregular hole diameters, and punch-through tears.
   - Primary Drivers: Spindle Cycles $> 8,500$ cuts, Spindle Feed Rate $> 280$ mm/min.
5. `nominal_in_control` (Correlates with `normal`):
   - Mechanism: All physical parameters operating within statistical process control limits.

SHAP TREEEXPLAINER ATTRIBUTIONS:
- For every analyzed batch, the system computes exact Shapley additive explanations:
  $$f(x) = \phi_0 + \sum_{j=1}^M \phi_j$$
  where $\phi_j$ represents the positive or negative contribution of parameter $j$ toward the classified failure mode.
- Renders local waterfall charts on the UI highlighting the top 4 contributing factors (e.g., "Hydraulic Pressure (+0.42 SHAP) pushed system into Crack state").

CUSUM (CUMULATIVE SUM) STATISTICAL PROCESS DRIFT:
- Detects subtle, systematic shifts in defect rates or station cycle times before upper specification limits are breached:
  $$S_i = \max(0, S_{i-1} + X_i - \mu_0 - k)$$
  where $k = 0.5\sigma$ is the reference allowance and $h = 4.0\sigma$ is the decision threshold. Triggers an advisory warning when $S_i > h$.

4.4 DETERMINISTIC ECONOMIC & PROFITABILITY CALCULATION MODEL

The economic engine uses exact, deterministic formulas rather than neural predictions, ensuring zero calculation error:
1. Scrap Loss:
   $$\text{Loss}_{\text{scrap}} = N_{\text{defects}} \times \text{Scrap Rate} \times \text{Unit Scrap Cost} \quad (\text{e.g., } \$50.00/\text{unit})$$
2. Rework Cost:
   $$\text{Loss}_{\text{rework}} = N_{\text{defects}} \times \text{Rework Rate} \times \text{Unit Rework Cost} \quad (\text{e.g., } \$30.00/\text{unit})$$
3. Throughput Penalty (Bottleneck Starvation):
   $$\Delta \text{Throughput} = \max(0, \text{Target Throughput} - \text{Actual Bottleneck Throughput})$$
   $$\text{Loss}_{\text{throughput}} = \Delta \text{Throughput} \times \text{Unit Contribution Margin} \quad (\text{e.g., } \$150.00/\text{unit})$$
4. Total Economic Impact:
   $$\text{Total Loss} = \text{Loss}_{\text{scrap}} + \text{Loss}_{\text{rework}} + \text{Loss}_{\text{throughput}}$$
   Aggregates into hourly, daily, and monthly financial metrics for executive visibility.

4.5 METALLURGY-GROUNDED WHAT-IF SIMULATION ENGINE

Unlike naive simulators that apply arbitrary linear scaling, the simulator models physical behavior based on AISI 4140 alloy steel metallurgy:
- Griffith Fracture Criterion (Cracks):
  Forming pressure above the 180.0 bar critical threshold exponentially increases micro-crack initiation probability. Reducing pressure from 188 bar to 172 bar reduces crack defect probability by up to 78%.
- Pourbaix Kinetics (Rust):
  Coolant pH below 7.2 enters the active corrosion zone for ferrous steel. Buffering pH to 7.6–7.8 neutralizes acid attack and reduces rust rate by 55%.
- Archard Abrasive Wear Equation (Scratches):
  Abrasive volume removed is proportional to normal load and sliding distance ($V = K \frac{W \cdot s}{H}$). Throttling conveyor speed from 1.25 m/s to 0.95 m/s reduces friction drag marks by 48%.

- Framework: PyTorch 2.0+, `torchvision`, `timm`.
- Dataset Partition:
  * Total Images: 12,000 (2,400 per class).
  * Split: Stratified 70% Train (8,400 images), 15% Validation (1,800 images), 15% Test (1,800 images).

  * Random Seed: 42 (ensures absolute reproducibility).
- Image Transforms & Augmentation Pipeline:
  * Training Transforms:
    1. `Resize((256, 256))`
    2. `RandomResizedCrop(224, scale=(0.8, 1.0))`

    1. `Resize((224, 224))`
    2. `ToTensor()`
    3. `Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225])`
- Optimization Hyperparameters:

  * Loss Function: `nn.CrossEntropyLoss(label_smoothing=0.05)` (prevents overconfidence).
  * Optimizer: `AdamW(model.parameters(), lr=1e-4, weight_decay=1e-4)`.
  * Learning Rate Scheduler: `CosineAnnealingLR(optimizer, T_max=epochs, eta_min=1e-6)`.
  * Precision: Mixed Precision training via `torch.amp.autocast('cuda')` and `torch.amp.GradScaler('cuda')`.
  * Batch Size: 32 (effective gradient accumulation if VRAM constrained).
  * Epochs: 10 – 15 epochs (early stopping patience = 5 on validation Macro F1).
  * Hardware: NVIDIA GPU (RTX 4050/3060+) or Apple Silicon MPS.
- Training Progress & Results:
  * Epoch 1: Train Acc: 94.67%, Val Acc: 100.0%, Val F1: 1.0000, Loss: 0.2315.
  * Epoch 5: Train Acc: 99.98%, Val Acc: 100.0%, Val F1: 1.0000, Loss: 0.2255.

7. DEPLOYMENT, BACKEND API & FRONTEND INTEGRATION
====================================================================================================

7.1 BACKEND API ARCHITECTURE (FastAPI)
The backend resides in `backend/app` and exposes structured REST endpoints:
- `POST /api/v1/vision/classify`:
  Accepts a single image or batch, runs EfficientNet-B4 with MC Dropout, returns class, confidence, uncertainty, and OOD flag.
- `POST /api/v1/vision/localize`:
  Generates Grad-CAM activation heatmap overlay (JPEG/PNG) and extracts bounding box coordinates with defect area percentage.
- `POST /api/v1/process/analyze`:
  Ingests process state telemetry (Model 1/2/3 CSV rows), detects active bottlenecks using Little's Law and utilization thresholds, and computes line efficiency.
- `POST /api/v1/root-cause/correlate`:
  Combines defect classification with process telemetry, runs the XGBoost RCA classifier, computes TreeSHAP feature attributions, and returns top causal drivers.
- `POST /api/v1/simulator/what-if`:
  Takes baseline vs. modified operating parameters, executes metallurgical fracture/corrosion equations, and returns predicted defect delta, throughput change, and net monthly savings.
- `POST /api/v1/copilot/chat`:
  Natural-language query endpoint answering operator inquiries by querying the pre-computed structured evidence chain.

7.2 FRONTEND DASHBOARD (Next.js 14 + React + TypeScript)
The frontend resides in `frontend/` and features:
- Quality Inspection Viewer: Interactive image canvas with toggleable Grad-CAM heatmap overlay and bounding box rendering.
- Factory Process Health: Real-time station utilization gauges (Apache ECharts) and React Flow process topology highlighting bottleneck stations in amber/red.
- Root-Cause Evidence Panel: SHAP waterfall charts showing exact parameter contributions toward failure modes.
- What-If Scenario Sandbox: Interactive parameter sliders (pressure, pH, conveyor speed, demand) with real-time recalculation of simulated profit delta.
- AI Factory Copilot Drawer: Conversational assistant providing natural language answers grounded in analytical evidence.

8. STEP-BY-STEP REPRODUCIBILITY & EXECUTION GUIDE
====================================================================================================

8.1 ENVIRONMENT SETUP
Prerequisites: Python 3.9 – 3.11, Node.js 18+, CUDA-capable GPU (recommended) or CPU.

Step 1: Activate virtual environment and install Python dependencies:
```bash
cd CMR_HACKATHON
source venv/bin/activate
pip install -r requirements.txt
```

Step 2: Install Frontend dependencies:
```bash
cd frontend
npm install
cd ..
```

8.2 EXECUTING MODEL TRAINING
To retrain and re-benchmark all models from scratch:
```bash
# Set Python path and run orchestrator
export PYTHONPATH="$PWD"
python3 models/train_all.py
```
This executes:
1. `models/process/train.py` -> Trains XGBoost Process Surrogate models.
2. `models/correlation/train.py` -> Trains XGBoost Root Cause Classifier & initializes SHAP explainer.
3. `models/vision/train.py` -> Trains EfficientNet-B4 Defect Classifier with AdamW & Cosine Annealing.
4. `models/vision/evaluate.py` -> Runs comprehensive 1,800-image test set evaluation and latency benchmarking.
5. Saves all checkpoints and summary reports to `models/weights/`.

8.3 LAUNCHING THE APPLICATION
Execute the unified startup script:
```bash
chmod +x run_app.sh
./run_app.sh
```
Or start services independently:
- Terminal 1 (FastAPI Backend):
  ```bash
  source venv/bin/activate
  export PYTHONPATH="$PWD"
  python3 -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 --reload
  ```
  API Documentation: http://localhost:8000/docs
- Terminal 2 (Next.js Frontend):
  ```bash
  cd frontend
  npm run dev
  ```
  Web Application: http://localhost:3000

8.4 VERIFYING BACKEND ENDPOINTS
To run automated test verification across all API endpoints:
```bash
export PYTHONPATH="$PWD"
python3 backend/test_all_endpoints.py
```
